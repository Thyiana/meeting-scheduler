# 会议室排期系统

一个黑白灰极简风格的会议室预约 / 排期管理网页，排期管理区间固定为 **2026-09-28 至 2026-09-30**。

## 功能

- **会议室管理**：动态添加 / 重命名 / 删除会议室，预约下拉菜单与看板颜色实时同步；每个会议室、每场会议的卡片颜色都可以自定义。
- **日程看板（FullCalendar 6）**：每个会议室单独一列，默认展开 08:00–20:00（夜间时段默认折叠），顶部可切换「显示全天 (24H)」，并提供「跳转到当前时间」定位按钮；看板上有实时移动的红色时间线（带 `HH:MM` 标签），已结束会议自动置灰，进行中的会议有呼吸灯高亮。点击/拖拽创建预约，点击事件弹窗编辑或删除。
- **搜索 / 筛选**：工具栏搜索框按「主持人」「会议关键词」实时过滤所有会议室的看板。
- **完整日期 + 双时区标注**：看板顶部与日期头均显示完整年份（如"2026年9月28日"），并在操作端和嘉宾端顶部醒目标注"本会议室所有预约时间均以新加坡时间（SGT）为准"。
- **紧急公告**：后台可发布/撤下一条全局横幅公告（如"Cinnamon Room 14:00 议程顺延 15 分钟"），嘉宾端和门头看板每 15 秒自动轮询显示，无需刷新。
- **一键清空测试数据**：后台"危险操作"区提供一键重置，需要先点击确认弹窗、再输入 `RESET` 二次确认才会真正执行，仅清空预约记录，会议室本身保留。
- **并发冲突防护**：嘉宾端和管理端都每 10 秒静默轮询一次最新排期；编辑保存时后端会校验 `updated_at`（乐观锁），如果这段时间内被别人改过，会提示"该预约已被他人修改，请刷新后重试"而不是静默覆盖。同一会议室同一时段仍然完全禁止重叠预约。
- **15 分钟缓冲时间提醒**：保存预约后，如果与同会议室前后相邻的会议间隔不足 15 分钟，会弹出非阻塞的提示 Toast（不会阻止保存，仅供参考）。
- **导出 Excel**：基于 SheetJS 一键导出当前全部排期为 `.xlsx`，总览 + 每个会议室单独一个 sheet，字段包含：序号、日期、星期、会议室（总览页）、开始时间、结束时间、会议主题、主持人/主讲人、联系电话/备注、参会名单链接，文件名按当天日期自动命名。
- **嘉宾扫码预约**：管理端侧边栏点「生成邀请二维码」，会读取本机在局域网中的 IPv4 地址并生成一个指向 `/guest` 的二维码。嘉宾手机连接同一 Wi-Fi 扫码即可打开专门的手机端页面，顶部有高亮的"当前选择：会议室 X"大字标题；新建预约使用日期 + 开始/结束时刻三个下拉选择器（15 分钟步长），而不是容易误触的网格拖拽；弹窗限高 90vh 可滚动，软键盘弹起也不会挡住提交按钮；提交成功/失败都有明显 Toast 提示。可以编辑/取消自己（或任何人）提交的预约——目前没有账号系统，所有人权限一致。
- **嘉宾端导出到个人日历**：预约详情弹窗提供「导出到日历 (.ics)」和「添加到 Google Calendar」两个按钮，前者直接下载单个会议的 `.ics` 文件（可导入任意日历 App），后者一键跳转 Google Calendar 添加事件页面。
- **门头看板模式（Signage）**：独立的 `/signage` 全屏页面，无侧边栏、无交互，专为投屏到会议室门口 iPad 或电视设计；自动显示当天各会议室排期，同样带实时红线、呼吸灯高亮、紧急公告横幅，每 10 秒自动刷新。
- **PWA 离线加载**：Service Worker 缓存了页面外壳（HTML/CSS/JS）以及最近一次成功获取的 `/api/meetings`、`/api/rooms` 响应。现场 Wi-Fi 断网或弱网时，嘉宾/门头页面仍能打开并显示最近一次缓存的排期快照（顶部会有"离线模式"提示），恢复联网后自动切回实时数据。
- **健康检查**：`/healthz` 提供一个不依赖鉴权的轻量探针（返回纯文本 `ok`），方便接入 UptimeRobot / cron-job.org 等外部 Ping 服务防止付费实例被平台判定为空闲。
- **中英双语**：所有页面右上角都有语言切换按钮（EN / 中文），点一下整页文字切换，包括表单、按钮、提示、报错信息；语言偏好记在浏览器本地。英文用 Arial，中文用微软雅黑（同一套字体栈按字符自动切换）。

## 已移除的功能

- **操作端第三方 iCal 日历同步**（订阅外部 `.ics` URL 写入会议室）已按需求整体删除，替换为上面的"嘉宾端导出到个人日历"（方向反过来：从系统导出单个会议给嘉宾，而不是从外部日历批量导入）。

## 技术要点（性能与稳定性）

- **SQLite**：使用 Node.js 22+ 内置的 `node:sqlite` 模块（无需 `better-sqlite3` 等原生编译依赖），启用 `WAL` 日志模式 + `busy_timeout`，进程收到 `SIGINT`/`SIGTERM`/`exit` 时执行 `wal_checkpoint(TRUNCATE)` 后再关闭连接，避免异常退出导致数据库死锁或产生游离的 WAL 文件。数据存放在 `DATA_DIR` 环境变量指定的目录（默认 `./data`），部署到 Render 等平台时应配置持久化磁盘，详见下方部署说明。
- **乐观并发控制**：`meetings` 表的 `updated_at` 字段作为版本戳，前端每次编辑提交时附带 `expected_updated_at`，后端不一致则返回 `409 MEETING_STALE`，从根本上防止两人同时编辑同一预约互相覆盖。
- **PWA 缓存策略**：静态资源走 cache-first（离线也能打开页面外壳），`/api/meetings` 与 `/api/rooms` 走 network-first（优先实时数据，失败时回退到最近一次缓存的快照），其余写操作（POST/PUT/DELETE）从不被 Service Worker 拦截。
- **前端依赖走国内 CDN**：FullCalendar 6、SheetJS、qrcodejs 默认使用 BootCDN，各 HTML 中同时预留了 jsDelivr 备用地址（注释形式），CDN 不可用时取消注释切换即可。

## 运行方式

> 需要 Node.js **22.5 以上**版本（内置 `node:sqlite`，不需要额外编译原生模块）。运行 `node -v` 确认版本。

```bash
npm install
npm start
```

默认监听 `http://localhost:3000`：
- 管理端：`http://localhost:3000/`
- 嘉宾端：`http://localhost:3000/guest`
- 门头看板：`http://localhost:3000/signage`

首次启动会自动创建 `会议室 A` / `会议室 B` 两个示例会议室，以及 SQLite 数据库文件 `data/scheduler.db`。

如需更换端口：

```bash
PORT=8080 npm start
```

## 部署到公网（以 Render 为例）

推到 GitHub 后连接 Render 会自动部署，但有一点必须注意：

**默认磁盘不是持久化的** —— 每次重新部署，服务器上的文件（包括 SQLite 数据库）都会被清空重置。

长期使用建议：

1. 升级到 Render 付费套餐（Starter 起），在服务设置里加一个 **Disk**（持久化磁盘），挂载路径比如 `/var/data`。
2. 环境变量加一条 `DATA_DIR=/var/data`。
3. 建议再配置一个外部 Ping 服务（如 UptimeRobot、cron-job.org）每几分钟访问一次 `https://你的域名/healthz`，防止实例被判定空闲而冷启动，现场使用时减少首次加载延迟。
4. 重新部署一次即可，代码已原生支持读取 `DATA_DIR`，无需改代码。
